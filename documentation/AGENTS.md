# Documentation maintenance

Read `documentation/0-index.md` before changing behavior, architecture, configuration, persistence, build, deployment, or user-facing workflows. Follow the matching route, inspect its source paths, and update the smallest accurate documents after verified changes.

Documentation must describe the current public repository only. Never add private project inventories, user paths, credentials, operational task history, generated browser evidence, or unpublished product implementation details.

Documentation closeout requires link/source-path validation and the application checks routed by `documentation/application/qa/test-suite.md`.
